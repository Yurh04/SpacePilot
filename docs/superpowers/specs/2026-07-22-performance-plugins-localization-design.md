# SpacePilot 性能、插件与本地化改造设计

日期：2026-07-22  
状态：已获用户设计批准，等待书面规格复核

## 目标

本次改造解决三个直接影响第一版可用性的问题：

1. 使用包含约 212 万条扫描记录、约 1 GB 持久化快照的真实数据时，页面点击必须保持响应。
2. Codex 已安装的 Plugins 必须能够被识别，并在对应 AI 应用内清晰展示。
3. 应用提供简体中文和英文界面，并跟随 macOS 系统语言自动选择；其他语言环境回退英文。

本次不重做 SQLite 存储格式，不增加顶级 Plugins 或 Skills 侧边栏入口，也不提供应用内手动语言切换。

## 方案选择

采用“后台统一生成轻量页面投影”的方案。

完整 `ScanSnapshot` 仍作为本地索引的领域数据存在，但 SwiftUI 页面不得在 `body`、计算属性或列表构建期间扫描完整 `snapshot.items`。快照加载或扫描结果更新后，`AppModel` 在后台任务中生成页面投影，并在主线程一次性发布轻量结果。

未采用以下方案：

- SQLite 分页查询：长期方向合理，但需要重做存储、搜索与分页协议，超出本次范围。
- 逐页面临时缓存：不能消除同类性能问题再次出现的结构性风险。

## 架构

### 后台投影流水线

新增统一的 `AppSnapshotProjection`，包含：

- `OverviewProjection`
- `StorageProjection`
- `ApplicationListProjection`
- `DeveloperAIProjection`

数据流如下：

1. `AppModel` 接收新的 `ScanSnapshot`。
2. 立即保留快照并取消旧投影任务。
3. 使用后台优先级任务构建 `AppSnapshotProjection`。
4. 新投影完成后，确认其快照 ID 仍为最新值。
5. 在主线程发布投影；各页面只读取投影数据。

如果投影尚未完成，页面显示本地化的准备状态。侧边栏、工具栏和窗口交互不能被阻塞。

### 投影规模约束

- 首页安全建议只保留展示所需的前若干条，不保存完整排序副本。
- Storage 的最大文件和旧文件列表各限制为 100 条，使用有界选择算法，不全量排序。
- 应用列表的关联文件空间按所有者一次性聚合，排序时只查询字典。
- Developer & AI 为每个 AI 应用预先生成数据条目、Plugins、Skills、空间合计及开发文件总量。
- 搜索只作用于轻量或有界集合，不重新扫描全部快照条目。

所有列表元素继续使用领域对象的稳定 UUID 作为标识。

## Plugins 与 Skills

### 清单兼容

`PluginManifest.skills` 必须兼容 Codex 插件中现存的两种形式：

- 单个目录字符串：`"./skills/"`
- 路径数组：`["skills/one", "skills/two"]`

目录字符串表示扫描该目录下包含 `SKILL.md` 的直接子目录。数组继续表示显式组件路径。路径必须经过现有的根目录约束与 `..` 拒绝规则，不能借兼容解析放宽安全边界。

### 展示位置

Plugins 和 Skills 保持归属于 AI 应用：

- 路径：`开发与 AI → Codex → 插件`
- 路径：`开发与 AI → Codex → 技能`

不新增顶级导航入口。

插件表显示：

- 名称
- 版本
- 来源
- 占用空间
- 包含的技能数量
- 管理方式

插件详情或关联说明必须能够区分插件包本身与插件提供的 Skills，计算空间时不得重复统计插件内的 Skill。

如果没有插件，界面显示明确空状态，并区分：

- 未安装插件
- 插件清单无法解析
- 插件路径无法访问

诊断信息不得展示对话或日志正文。

## 中英双语

使用 Apple 标准 String Catalog 管理用户可见文案：

- 基础语言：英文
- 支持语言：简体中文 `zh-Hans`
- 语言选择：跟随 macOS 系统语言
- 其他语言：回退英文

本地化范围包括：

- 侧边栏与导航标题
- 按钮、菜单、上下文菜单和表头
- 空状态、加载状态和确认对话框
- 扫描阶段、进度与错误提示
- 风险等级、分类、Skill 范围与管理状态
- 设置、隐私说明和诊断导出界面
- Plugins 与 Skills 模块
- 无障碍标签

产品名、文件路径、应用名、插件名、Skill 名和版本号不翻译。

领域枚举不再直接返回固定英文展示文本。界面层通过本地化键生成显示文案，避免把本地化状态写入持久化快照。

## 错误与状态处理

- 投影任务失败时保留快照，显示可重试的本地化错误，不阻塞其他页面。
- 新扫描开始或快照变化时，旧投影不得覆盖新投影。
- 插件单个清单失败不得中止整个扫描；错误进入插件诊断摘要。
- 插件路径不可访问时不得猜测插件内容或占用空间。
- 没有数据、正在准备和解析失败使用不同界面状态。

## 测试策略

### 自动测试

- `PluginManifest` 同时解码字符串目录与字符串数组。
- 目录形式能够发现目录下的 Skills，并保持 `parentPluginID` 关联。
- 不安全组件路径继续被拒绝。
- 扫描结果把发现的 Plugins 关联到 Codex，而不是 Claude 或普通 AI 应用。
- 页面投影对同一条目不重复计数。
- Storage 列表保持 100 条上限和正确顺序。
- Developer & AI 投影正确生成插件、技能和空间总计。
- 新旧投影任务不能发生过期结果覆盖。
- String Catalog 中英文键完整，关键导航与状态文案有简体中文值。

### 真实数据验证

使用当前本机约 1 GB 快照验证：

- 快照加载期间仍可切换侧边栏。
- 投影准备期间立即显示进度反馈。
- 投影完成后，在首页、储存空间、应用程序、开发与 AI 之间重复切换，不发生主线程长时间满载。
- Codex 插件页显示本机已安装插件，其中应包括具有有效清单的 `product-design` 等插件。
- 将系统首选语言分别设为简体中文和英文后，重启应用显示相应语言。

## 验收标准

- 点击任何主导航项后立即出现选中状态或加载反馈，不出现 macOS“应用程序没有响应”。
- 投影缓存完成后，页面切换不遍历完整 `snapshot.items`。
- 真实插件清单的字符串 `skills` 字段不再造成整条插件记录丢失。
- Plugins 在 Codex 内可见，空状态与解析失败状态可区分。
- 所有主要用户流程均有中英文文案，并跟随系统语言。
- 完整自动测试通过，调试构建和启动成功。

## 后续方向

后续版本可把 1 GB JSON 快照改为规范化 SQLite 表并引入分页查询，以进一步降低约 1 GB 的常驻内存。本次投影架构应保持与该存储迁移兼容，但不提前实现分页层。
