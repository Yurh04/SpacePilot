# 决策记录

本文档记录长期有效的产品和架构决策。如果某个决定会影响安全、隐私、兼容性或子系统边界，修改它时必须新增带日期的记录。

## D-001——原生 Apple Silicon macOS 应用

**状态：** 已接受
**决策：** 使用 Swift 6、SwiftUI、少量 AppKit 互操作和 SwiftPM；只支持 Apple Silicon 和 macOS 15+。
**原因：** 文件系统工具需要直接使用 macOS API、较低运行开销、原生表格和窗口，以及更小的分发体积。

## D-002——完全本地的元数据智能

**状态：** 已接受
**决策：** 只持久化路径、大小、时间、所有权、风险、置信度和操作历史，不保存对话或日志正文。
**原因：** 产品需要解释储存空间所有权，但不能成为敏感内容索引或造成 AI 数据泄露。

## D-003——持久化索引和小范围刷新

**状态：** 已接受
**决策：** 启动时读取最近的 SQLite 快照，缓存目录统计，通过 FSEvents 使相关数据失效并刷新受影响范围。普通页面切换不能递归重扫整个用户目录。
**原因：** 文件系统元数据遍历是主要的延迟和内存成本，持久化的所有权智能才是产品核心。

## D-004——Spotlight 只是加速层

**状态：** 已接受
**决策：** 使用 Spotlight 发现应用关联候选项，但不把它作为完整性或目录大小的唯一来源。
**原因：** Spotlight 可能存在延迟、不完整或权限限制。

## D-005——按需分析应用详情

**状态：** 已接受
**决策：** 首先快速生成应用清单，用户选中应用后再计算深层关联大小，并复用缓存结果。
**原因：** 用户需要快速看到应用列表，而且一次使用过程中多数应用详情不会被打开。

## D-006——解释所有权，而不只是匹配名称

**状态：** 已接受
**决策：** 每条关联必须包含证据、置信度、所有权和风险。Bundle、容器、Team 身份和验证过的知识规则优先于名称模糊匹配；有歧义的结果不默认选中。
**原因：** 储存管理工具既要尽可能找全，也不能误删共享数据或名称相似应用的数据。

## D-007——清理必须可恢复并重新验证

**状态：** 已接受
**决策：** 用户选择准确路径；敏感项目单独确认；Managed 项目禁止处理；执行前重新验证文件身份；有效项目移到废纸篓，不永久删除。
**原因：** 文件在扫描后可能已经变化，错误清理必须可以恢复。

## D-008——Plugin 和 Skill 属于 AI 应用模块

**状态：** 已接受
**决策：** Plugin、Skill 和 CLI 工具放在“开发与 AI”工作区中，而不是顶层导航。全局、Codex、Claude、Plugin 提供和系统管理范围均需保留。
**原因：** 用户更容易通过使用或管理这些资产的 AI 工具理解它们。

## D-009——不移动或修改受管理的 Skill/Plugin

**状态：** 已接受
**决策：** SpacePilot 可以识别范围、重复、冲突和覆盖关系，但不在不同根目录间移动 Skill，也不直接修改 Plugin 或系统缓存。
**原因：** 移动可能改变 Agent 行为，受管理内容也可能在更新时被覆盖。

## D-010——界面上合并 ChatGPT 与 Codex 产品族

**状态：** 已接受
**决策：** 汇总当前 ChatGPT/Codex 应用及本地资产的总量和导航，同时保留底层路径的实际归属。
**原因：** 当前 macOS 产品体验和本地资源存在重叠，分开显示会低估总占用并让用户困惑。

## D-011——异步加载期间保持桌面布局稳定

**状态：** 已接受
**决策：** 主侧边栏和应用列表使用明确且稳定的宽度约束；加载状态和新计算出的大小不能改变列宽。原生分组表格的行映射必须包含标题行和折叠状态。
**原因：** 异步分析曾导致分栏跳动，分组存在时直接使用扁平行号还会定位错误文件。

## D-012——外部分发不依赖 Mac App Store

**状态：** 已接受
**决策：** 支持网站或 Homebrew 等方式分发，但公开版本必须经过 Developer ID 签名和 Apple 公证；ad-hoc 签名仅用于开发检查。
**原因：** Mac App Store 可以不使用，但 Gatekeeper 信任和安全分发不能省略。

## D-013——最近空间变化使用持久化基线和 FSEvents 回放

**状态：** 已接受
**决策：** 最近变化只保存文件元数据、大小差值、磁盘容量采样和覆盖缺口。SQLite 保存基线与 31 天事件，FSEvents 游标和变化结果原子前进；完整扫描负责周期校准。单项变化以 100 MiB 为展示阈值，小变化按目录聚合，1 GiB 以上强调。
**原因：** 只比较应用打开期间的两次扫描会漏掉关闭期间的变化；只看磁盘可用空间又无法解释具体来源。持久化基线加事件回放可以在不索引内容的前提下提供可追溯结果，并用缺口记录诚实表达系统事件历史并非永远完整。

## D-014——整盘占用与已分析分类必须分开

**状态：** 已接受
**决策：** 整盘已使用容量来自卷容量减可用容量；分类只统计 SpacePilot 实际扫描和识别的数据。两者的差额单列为“未分析/系统占用”，不能注入 `.system` 分类，也不能提供虚假的项目数量或清理入口。应用包可以加入容量图表，但不冒充可浏览的 `ScannedItem`。
**原因：** 普通应用无法使用 macOS 系统设置的私有储存分类能力。把差额归为“系统”会让用户误以为 SpacePilot 已经分析并能解释这些空间，既不准确也无法验证。

## D-015——最近变化的安全标记必须保守且可追溯

**状态：** 已接受
**决策：** 最近变化沿用扫描风险模型，并把风险级别保存到变化基线和事件记录。只有仍存在、未聚合且风险明确为 `safe` 的单项才显示“可安全清理”；已删除、聚合和风险未知的记录都不标为安全。用户缓存和日志根目录可在追踪阶段明确派生为 `safe`，其他路径不能仅凭名称或大小推断。
**原因：** 最近变化用于解释空间变化，不等同于清理计划。保守标记可以帮助用户缩小检查范围，同时避免把历史缺失、目录聚合或身份不明的数据误导为可直接删除。
